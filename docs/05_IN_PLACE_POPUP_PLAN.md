# سند معماری و طرح اجرایی پاپ‌آپ در کنار باکس نوشتن
## In-Place Popup Architecture & Implementation Plan (v1.0)

**تاریخ تدوین:** ۱۹ سپتامبر ۲۰۲۶  
**وضعیت:** مستندسازی‌شده و آماده برای بحث و بررسی جزئیات (Pending Alignment)  
**پلتفرم هدف:** Ubuntu 24.04 (Wayland / GNOME 46 / Pop-Shell Tiling) & Windows (Architecture-Ready)

---

## ۱. پیشینه و مسئله‌شناسی (Problem Statement)

در جریان تست‌های اولیه نمونه آزمایشی (Spike HUD) در محیط واقعی کاربر با میزکار گنوم ۴۶ و افزونه مدیریت پنجره **Pop-Shell**، دو مسئله حیاتی در تجربه کاربری شناسایی شد:

1. **تداخل با تایلینگ (Pop-Shell Window Tiling):**
   * کاربر از حالت تایلینگ پیش‌فرض (`tile-by-default: true`) استفاده می‌کند.
   * باز شدن یک پنجره مستقل سیستم‌عامل (`Gtk.ApplicationWindow`) باعث می‌شد پاپ‌شل بلافاصله صفحه کاربر را نصف کرده، ادیتور یا پنجره فعال را فشرده کند و پنجره برنامه را در کنار آن تایل کند. با بستن پنجره نیز مجدداً صفحه تغییر ابعاد می‌داد.
   * این رفتار پیوستگی ذهنی کاربر در حین نوشتن را مختل می‌کند.

2. **محل قرارگیری پاپ‌آپ و ایزولاسیون Wayland:**
   * پاپ‌آپ نباید تمام صفحه را اشغال کند و باید به صورت یک کارت فشرده **دقیقاً در کنار باکس نوشتن / مکان هایلایت متن** ظاهر شود تا فوکوس چشم کاربر تغییر نکند.
   * در محیط Wayland، پروتکل امنیتی سیستم‌عامل به برنامه‌های مستقل کلاینت اجازه دسترسی به مختصات اشاره‌گر ماوس یا کرسر متن در سایر برنامه‌ها را نمی‌دهد. همچنین دستوری به نام `set_position(x, y)` در پروتکل لایه پنجره وجود ندارد؛ در نتیجه پنجره در گوشه بالا-چپ مانیتور `(0, 0)` قرار می‌گرفت.

## ۲. یافته‌های فنی و مهندسی معکوس الگوهای موفق

در تحلیل افزونه فعال سیستم کاربر (`clipboard-indicator` با کلید میانبر `Super + V`)، مشخص شد که این ابزار دقیقاً همان تجربه مورد انتظار را پیاده‌سازی کرده است:

```javascript
// بخشی از منطق افزونه clipboard-indicator در گنوم
const [x, y] = global.get_pointer();
this._cursorActor.set_position(x, y);
this.menu.sourceActor = this._cursorActor;
this.menu.toggle();
```

### مزایای معماری کامپوزیتور (Compositor-Level UI):
1. **مصونیت ۱۰۰٪ از تایلینگ:** چون المان یک «پنجره کلاینت» نیست بلکه یک Actor داخلی شل گنوم است، Pop-Shell و Mutter آن را به عنوان پنجره تشخیص نمی‌دهند و اصلاً امکان تایل کردن آن وجود ندارد.
2. **قرارگیری دقیق در کنار باکس نوشتن:** به دلیل دسترسی مستقیم شل گنوم به `global.get_pointer()`، پاپ‌آپ دقیقاً در کنار اشاره‌گر ماوس (که همان لحظه برای سلکت متن استفاده شده) باز می‌شود.
3. **سرعت بسیار بالا:** المان از قبل در حافظه کامپوزیتور آماده است و تاخیر لود پروسه جدید (زیر ۱۵ میلی‌ثانیه) ندارد.
4. **رفتار خودکار پاپ‌آپ:** با کلیک در هر نقطه دیگر از صفحه یا فشردن `Esc` بلافاصله محو می‌شود.

## ۳. معماری تفکیک‌شده (Decoupled / Hexagonal Architecture)

برای اینکه انتخاب لایه نمایش گنوم به توسعه‌پذیری پروژه در پلتفرم‌های دیگر (به‌ویژه ویندوز) آسیبی نزند، معماری به دو لایه کاملاً مجزا تفکیک می‌شود:

```
┌─────────────────────────────────────────────────────────────┐
│             هسته مرکزی و مشترک برنامه (Core Backend)         │
│  مستقل از سیستم‌عامل — پیاده‌سازی با Python                  │
│                                                             │
│  ├── engine.py       # اتصال به مدل هوش مصنوعی (Groq/Gemini) │
│  ├── prompts.py      # پرامپت استخراج نیت و ساختار JSON     │
│  ├── storage.py      # دیتابیس محلی ذخیره رویدادها (SQLite) │
│  └── runner.py       # ورودی اجرای سریع و پردازش درخواست‌ها │
└──────────────────────────────┬──────────────────────────────┘
                               │  Fast Local IPC (CLI / JSON)
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
┌──────────────────────────────┐       ┌──────────────────────────────┐
│  لایه نمایش اوبونتو (GNOME) │       │   لایه نمایش ویندوز (Win32)  │
│  افزونه سبک GNOME Shell      │       │   پنجره Frameless بدون کادر  │
│  - شورتکات Ctrl+Alt+G        │       │   - خواندن GetCursorPos      │
│  - نمایش در [x, y] ماوس      │       │   - باز شدن کنار مکان‌نما     │
│  - عدم تایلینگ در Pop-Shell  │       │   - اعمال با شورتکات ویندوز  │
└──────────────────────────────┘       └──────────────────────────────┘
```

## ۴. اجزای فنی و طرح پیاده‌سازی لینوکس

### بخش اول: هسته پردازشی (Core Engine & Storage)
مسیر: `core/` در ریشه مخزن
* **`core/prompts.py`:** تعریف دقیق پرامپت استخراج نیت با خروجی JSON تک‌مرحله‌ای طبق قرارداد BRD.
* **`core/engine.py`:** ارسال درخواست به ارائه‌دهنده پرسرعت (Groq با مدل Llama 3.3 یا Gemini Flash) با مدیریت خطای شبکه و فال‌بک لوکال/ماک.
* **`core/storage.py`:** ذخیره لاگ تغییرات در پایگاه داده محلی SQLite با ثبت فیلد `accepted` (جهت شناسایی نقاط ضعف در فاز یادگیری).
* **`core/runner.py`:** رابط دریافت متن، صدا زدن هوش مصنوعی، و بازگرداندن خروجی ساختاریافته به فرمت JSON به خروجی استاندارد.

### بخش دوم: لایه نمایش گنوم (GNOME Shell UI Adapter)
مسیر: `~/.local/share/gnome-shell/extensions/writing-companion@sajjad.local/`
* **`metadata.json`:** تعریف افزونه برای پوسته GNOME 46.
* **`extension.js`:**
  * ثبت کلید میانبر سراسری `<Primary><Alt>g`.
  * دریافت متن سلکت‌شده از طریق `St.Clipboard` (نوع Primary).
  * ایجاد یک جعبه پاپ‌آپ زیبا در مختصات `global.get_pointer()`.
  * نمایش وضعیت در حال پردازش (Thinking / Loading).
  * فراخوانی غیرهمزمان (Async Subprocess) هسته پایتون.
  * رندر پاسخ شامل: متن اصلاح‌شده، باکس زرد رنگ برداشت معنایی فارسی («💡 منظور: ...»).
  * کنترل کیبورد: کلید `Enter` برای اعمال و `Esc` برای بستن پاپ‌آپ.
  * شبیه‌سازی کلید برای پیست خودکار متن (یا کپی در کلیپ‌بورد).

## ۵. موضوعات و تصمیمات باز برای همفکری و گفتگو (Open Discussion Topics)

پیش از ورود به کدنویسی نهایی، این نکات باید مورد تایید و بررسی قرار گیرند:

1. **نحوه اعمال متن پس از زدن Enter:**
   * *حالت الف (Auto-Paste):* به محض زدن Enter، متن نه تنها در کلیپ‌بورد کپی شود بلکه با شبیه‌سازی رویداد کلید (`Shift+Insert` یا `Ctrl+V`) بلافاصله جایگزین متن هایلایت‌شده قبلی شود (جریان کاری با صفر کلیک اضافه).
   * *حالت ب (Copy-Only):* متن در کلیپ‌بورد کپی شده و پاپ‌آپ بسته شود؛ کاربر خودش در صورت تمایل `Ctrl+V` بزند.
2. **ارائه‌دهنده پیش‌فرض هوش مصنوعی (AI Provider Choice):**
   * برای کاربرد بلادرنگ (Real-time)، تاخیر پاسخ باید زیر ۵۰۰ میلی‌ثانیه باشد.
   * گزینه‌ها: Groq API (بسیار سریع، حدود ۲۰۰ تا ۳۰۰ میلی‌ثانیه)، Gemini 1.5/2.0 Flash (دقت بالا و درک زبان فارسی بسیار قوی)، یا مدل محلی Ollama (آفلاین ولی نیازمند منابع پردازشی).
3. **طراحی بصری و فونت پاپ‌آپ:**
   * تنظیم فونت خوانا برای متن فارسی (مانند Vazirmatn یا فونت پیش‌فرض سیستم) در کنار متن انگلیسی.
   * استایل تیره (Dark Mode) هماهنگ با تم کلی گنوم کاربر.
4. **رفتار در صورت عدم انتخاب متن (Empty Selection Fallback):**
   * آیا در صورتی که متنی سلکت نشده باشد، یک کادر کوچک ورودی (Input Field) در همان پاپ‌آپ باز شود تا کاربر بتواند مستقیم تایپ کند، یا صرفاً پیام راهنما نمایش داده شود؟
